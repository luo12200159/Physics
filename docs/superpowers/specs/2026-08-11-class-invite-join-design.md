# Windows 局域网班级服务与双端加入修复设计

日期：2026-08-11
目标版本：3.1.7（以 `version.json` 为唯一版本源）

## 1. 已确认根因

当前安装包没有可用的班级服务：Windows WebView2 的持久化存储仍保留
`http://127.0.0.1:8787`，Android 也保留了
`https://appassets.androidplatform.net` 这一资源宿主地址。前者没有进程监听，后者不是班级
API。`classroom-client.js` 又会在请求失败时显示本机保存的 owner capability 中缓存的旧班级，
所以页面看似有班级，但创建、删除、生成邀请和加入都无法得到服务端确认。

重新打包静态文件不能修复该问题；双端班级关系需要一个可访问且持久化的服务。

## 2. 已选择方案与边界

采用“Windows 电脑作为局域网班级主机”的方案：Windows 版启动时同时启动一个随安装包
交付的轻量班级服务；Android 与其他 Windows 设备在同一 Wi-Fi/热点内连接该服务。该方案
不依赖外部云服务器或管理员账号，同时保留未来配置公共 HTTPS 班级服务的能力。

明确边界：

- 班级跨设备功能仅在师生设备能够访问同一局域网主机时可用。
- 教师电脑关闭、休眠，或路由器启用客户端隔离时，班级操作不可用；本机题库和学习记录
  仍可离线使用。
- 本版本不宣称互联网异地同步。需要异地使用时仍应部署现有 Fastify/PostgreSQL 服务并
  配置 HTTPS 地址。
- Android 不承担班级主机职责；Android 教师可以连接 Windows 主机后创建和管理班级。

## 3. 组件设计

### 3.1 Windows 局域网服务

新增独立的 .NET Framework 可执行程序 `物理研习室-班级服务.exe`，由 Windows 启动器以
隐藏窗口启动和监管。它使用 `TcpListener` 监听 `0.0.0.0:8788`，避免 `HttpListener`
对 URL ACL/管理员权限的依赖。服务只实现应用实际需要的 JSON HTTP API，并限制请求头、
请求体大小、方法和路径。

数据保存在：

`%LOCALAPPDATA%\物理研习室\ClassroomService\classroom-data-v1.json`

写入采用进程内锁、临时文件、刷新到磁盘和原子替换。保存失败时返回明确错误，绝不向客户
端报告成功。服务数据与 WebView localStorage 分离，卸载默认保留用户数据；现有学习档案不
迁移、不删除。

服务另监听固定 UDP 发现端口。收到应用定义的随机 nonce 发现报文后，只返回协议版本、服务
实例 ID、HTTP 端口和可用局域网地址，不返回班级、成员、邀请码或 capability。

### 3.2 双端原生传输适配器

局域网服务使用私有地址 HTTP。为了不降低 WebView 的混合内容、任意网页加载和文件访问安全
策略，Web 页面不直接放开 HTTPS 到任意 HTTP 的 `fetch`：

- Windows：通过现有 WebView2 消息桥接执行严格限制的局域网班级请求和 UDP 发现。
- Android：通过现有 Android JS bridge 执行严格限制的局域网班级请求和 UDP 发现。
- 适配器只接受 loopback 或 RFC1918/链路本地地址、固定端口和 `/health/live`、`/v1/`
  路径；禁止重定向、userinfo、任意公网 HTTP、文件协议和非班级路径。
- 已配置的公共 HTTPS 服务仍使用现有 `fetch` 传输，不经过局域网桥接。

所有请求都有连接/读取超时。只读 GET 最多重试一次；创建、删除、加入、刷新邀请等变更请求
不自动重放，依靠 `Idempotency-Key` 保证用户主动重试安全。

### 3.3 客户端服务选择

`classroom-client.js` 按以下顺序选择服务：

1. 二维码携带且通过私有地址校验的局域网服务地址；
2. 用户明确保存的有效公共 HTTPS/私有局域网地址；
3. Windows 本机服务 `http://127.0.0.1:8788`；
4. 原生 UDP 发现返回的局域网服务列表。

手工输入邀请码时，如当前服务不可达，客户端发现局域网主机并逐一调用加入 API；以服务端
确认邀请码有效的第一个响应为准。无效邀请码与服务不可达分别显示，不能写入假的已加入状态。

升级时仅清除/迁移 `physics-classroom-config-v1` 中已确认无效的旧地址：
`127.0.0.1:8787`、`localhost:8787` 和 `appassets.androidplatform.net`。迁移不触碰题库、
学习记录、学生档案、激活信息或备份。旧 owner cache 标记为“旧本机记录，未同步”，可由用户
移除；它不得再被渲染为在线班级。

## 4. 权限与身份模型

- 创建班级不要求管理员账号、教师邀请码或服务端 teacher 角色。
- 创建只要求去除首尾空格后的班级名称非空；同名班级允许存在，唯一标识为 UUID `class_id`。
- 创建成功后服务生成 256 位随机 owner capability，只向创建请求返回一次；磁盘只保存
  SHA-256 摘要。客户端将原始 capability 保存在创建者本机应用存储。
- owner capability 只授权其对应班级的读取、删除、邀请码、成员和分组管理。其他班级返回
  403。
- 学生邀请码使用密码学安全随机数生成 22 位 Base64URL 字符，磁盘保存 SHA-256 摘要；
  冲突时重新生成。
- 学生首次加入时服务生成不可预测的学生会话 token；成员唯一键为
  `(class_id, student_identity_id)`，重复加入返回现有 membership，不重复插入。
- 邀请码和二维码只授予 student 权限，绝不包含或返回 owner capability。
- 删除班级由 owner capability 鉴权。删除采用归档状态，并在同一原子写入中撤销邀请码和成员
  的有效班级关系；旧邀请码随后返回“班级不存在或已失效”。独立学习历史不删除。

## 5. API 合同

局域网服务复用当前客户端路径与响应结构，至少提供：

- `GET /health/live`
- `POST /v1/classes/anonymous`
- `GET /v1/classes/:classId`
- `DELETE /v1/classes/:classId`
- `POST /v1/classes/:classId/invites`
- `POST /v1/invites/join-anonymous`
- `GET /v1/classes`
- `GET /v1/classes/:classId/roster`
- `PATCH /v1/memberships/:membershipId`
- `GET|POST /v1/classes/:classId/groups`
- `PATCH /v1/account/self`

班级详情页当前还会读取学情摘要、复核、作业和报告端点。局域网服务提供与现有客户端兼容的
最小实现：暂无数据时返回空集合；同步写入后返回实际保存的数据。不能以 404/网络错误导致整个
班级详情加载失败。

错误语义保持明确：400 参数错误、401 缺少身份、403 无权管理、404 班级/邀请码不存在或
已失效、409 真实冲突、413 请求过大、429 请求过频、5xx 持久化或服务异常。只有无法建立连接
或超时才显示“班级服务不可达”。

## 6. 邀请码与二维码流程

创建班级成功后立即生成一枚有效邀请码并进入班级详情。详情显示班级名称、班级 ID、当前学生
数、邀请码、二维码、复制、刷新邀请码、学生列表和删除班级。

二维码使用现有 scheme，并增加经过校验的局域网服务地址：

`physicsstudio://join?class_id=<UUID>&code=<22位邀请码>&server=http%3A%2F%2F<LAN-IP>%3A8788`

摄像头、二维码图片和手工输入最终统一调用 `joinClassByInviteCode()`：

- 摄像头/图片只解析纯邀请码或上述结构化 payload；
- payload 中的 server 必须是私有局域网地址和固定端口；
- 解析成功不等于加入成功，只有服务端返回 membership 后才保存班级关系；
- 相机不可用时继续提供图片和手工输入；
- 学生加入后可以修改班级内备注名，不能提升角色。

刷新邀请码会先生成并持久化新邀请码，再使旧邀请码失效。二维码同步更新。

## 7. 启动、网络与故障呈现

Windows 启动器负责：启动服务、等待健康检查、将本机服务状态交给 WebView、退出时请求服务
正常停止。若端口被其他可信实例占用则复用健康实例；若被无关进程占用，显示“8788 端口被
占用”并提供诊断，不静默回退。

首次监听局域网可能触发 Windows 防火墙提示。应用显示具体说明；若入站被阻止，Windows 本机
仍可使用，但 Android 无法连接。Android 发现不到服务时区分 Wi-Fi 未连接、路由器客户端隔离、
教师电脑服务未运行和超时，不把这些情况映射成邀请码错误。

恢复网络后重新发现并同步。同步队列只保存已有学习同步事件；创建、删除、加入和邀请码操作
不允许离线排队为“成功”。

## 8. 测试与发布验收

测试先行，覆盖：

- 旧错误 URL 迁移且学习/激活存储不变；
- 服务持久化重启、原子写入失败、请求大小和路径限制；
- 无教师邀请创建同名班级、UUID 唯一、owner 权限隔离；
- 邀请码唯一、刷新后旧码失效、二维码不含 owner token；
- 手工、摄像头结果和图片结果统一进入同一加入函数；
- 重复加入幂等、学生不能管理/删除、其他 owner 不能越权；
- 删除后邀请码失效、学生同步移除，独立学习记录仍在；
- Android/Windows 原生适配器只允许私有局域网班级路径；
- 服务不可达不伪造加入或创建成功；恢复后可以重新同步；
- 安装器包含并启动局域网服务，Windows 与 Android 发布包包含同一 Web 资源版本。

自动验证包括仓库 `npm run qa`、新增局域网服务集成测试、Windows 编译/安装包检查、Android
安全 QA 与 APK 构建。若真实双机网络受当前环境限制，发布前仍必须在一台 Windows 主机和一台
Android 真机上完成：创建 → 生成邀请码/二维码 → 手工加入 → 扫码加入 → 刷新邀请码 → 删除
→ 两名学生刷新确认失效。

## 9. 不在本次范围

- 不替代现有公共 HTTPS/Fastify 服务；两种服务使用相同客户端合同。
- 不实现互联网穿透、云托管、远程 NAT 穿透或自动配置路由器。
- 不修改现有题目 ID、学习档案结构、激活机制或离线学习能力。
- 不通过降低 WebView、Android 网络或 QA 安全策略来换取局域网连接。
